# 市场调研工作流

把一个"产品点子"变成一份数据驱动的市场调研报告。适用于硬件、消费品、软件与服务类产品。

**核心特点**

- 数据优先：每节先表后文，能用表格说清的不写段落
- 全程溯源：每个数据点带来源、日期、置信度
- 人机分工：AI 负责检索、建表、分析、组装；关键决策与数据核验由人确认（全流程设三个人工关卡）
- 六板块框架：政策 / 空间与发展 / 市场规模 / 竞品 / 定价 + 技术与外观专利

## 五个贯穿性原则（执行任何步骤都遵守）

1. **数据溯源强制**：每个数据点带 来源 + 日期 + 置信度分级（★★★ 官方或多源一致 / ★★ 单一来源或转述 / ★ 估算）
2. **找不到就写"未获取"**：禁止用合理推测填充；估算必须标注假设
3. **数据优先**：能用表格说清的不写段落；每节先表后文
4. **中间产物落盘**：关键词地图、来源清单、商品数据表全部保留，供复查与增量更新
5. **取数合规**：只采公开数据；只用本人实名账号；遇风控降频、不绕过；采集内容仅用于本次调研分析；保持人工兜底路径

## 流程总览

```
用户输入：产品点子

    │

    │

Step 2  调研（六板块）
    ├─ 2.0 商品数据表 ────────► CSV ─────────┐

```

## Step 0 · 需求澄清

把用户的"解决方案"翻译成可调研的"问题"——这一步决定后面所有检索的范围。跳过它，调研边界就只能靠猜。

**做法**：对话式提问（不必一次问完，随聊随确认），六问：

1. **目标用户**：谁、什么场景、支付能力
2. **核心任务**：用户要完成的 Job 是什么
3. **现有替代**：用户现在怎么解决（包括"什么都不做"和"手工凑合"）
4. **交付形态**：硬件 / 软件 / 服务 / 内容
5. **价格意图**：高端 / 大众 / 极致性价比
6. **调研边界**：什么算"同类产品"？给出纳入与排除标准

**硬性要求**

- 第 2 项必须从用户视角写，禁止出现产品名词（写"帮人挑衣服"，不写"AI 穿搭 App"）
- 第 6 项必须由用户确认，不得自行决定
- 缺少任一项时先问，不要猜

**产出**：调研简报（Markdown）——6 项内容 + 3 个你认为最大的不确定性。

**〔人工关卡 1〕** 简报写完先给用户过目确认，再进 Step 1。

---

## Step 1 · 关键词地图

为一个可能还没有品类名的产品，找出"市面上同类产品都叫什么"。产出的词表直接决定 Step 2 能覆盖多少商品与来源——词表越全，数据底座越全。

**做法**（完整方法见 `references/keyword-map.md`）：

- **八角度展开**候选词：结构/形态、品类、材质/技术、场景、人群、行业术语、品牌、英文
- **五个高质量词源**（按优先级）：专利检索 → 行业术语 → 电商搜索联想 → 品牌顺藤摸瓜 → 行业报告与媒体
- **命中验证循环**：每个候选词实搜一次，命中则保留并从结果继续挖新词，循环到不再出现新词（信息饱和，通常 3-4 轮）

**产出**：关键词地图（表格：词 | 类型 | 来源 | 命中判定）+ 类似产品清单（按结构接近度分组，附价格区间）。

**〔人工关卡 2〕** 与用户确认词表和产品清单后，再进 Step 2。

---

## Step 2 · 调研（六板块）

2.1 政策、2.2 空间与发展、2.3 市场规模、2.4 竞品、2.5 定价、2.6 技术与外观专利。其中竞品与定价两板块的数据底座是 2.0 建的商品数据表。

### 2.0 商品数据表（先做，其余板块依赖它）

不是调研的副产品，而是人机协作的接口：AI 把能采集的列全部填上，采集不到的标「待核验」留给人工补。完整规范（11 列列定义、采集范围、人工补表闭环、合规要求）见 `references/data-collection.md`。

流程：用 Step 1 词表检索采集 → 建表（CSV）→ 标「待核验」→ **〔人工关卡 3〕** 用户补表 → AI 读回表，作为 2.4 / 2.5 的唯一数据源。

### 2.1 - 2.6 各板块

每个板块的检索提示词、数据呈现要求清单、硬性要求见 `references/dimensions.md`，执行时逐条落实。每个板块的「数据呈现要求」表格必须全部出现在最终报告里，不得省略。

**每板块通用规则**：

```
- 每个数据点带：来源 + 日期 + 置信度（★★★ 官方/多源一致、★★ 单一来源/转述、★ 估算）
- 查不到就写"未获取"，禁止用合理推测填充
- 输出中文；数据段落不放 emoji
- 数据优先：每节先给表格，再给解读
- 销量必须标口径：X+人付款（人数模糊值）/ 30天引单量（联盟渠道）/ 月销量（全站），三者禁止混算
```

**执行说明**：六个板块相互独立，若运行环境支持并行子任务，可并行推进；但 2.4 / 2.5 必须等 2.0 的表补完才能开工。

---

## Step 3 · 报告组装

把六板块产物组装成一份报告。固定结构（执行摘要 / 研究方法与数据说明 / 六板块展开 / 简要建议 / 风险与不确定性 / 附录）、行文规则、篇幅配比（主体 70%），见 `references/report-template.md`。

组装前先确认：六个板块的「数据呈现要求」表格是否全部就位——缺表先补调研，再组装。

---

## Step 4 · 导出与交付

**交付物两个**，同前缀同日期命名，排序时自然配对：

| 交付物 | 文件 |
|---|---|
| 调研报告 | `{产品名}-市场调研报告-{日期}.md` + `.pdf`（PDF 供阅读与转发） |
| 商品数据表 | `{产品名}-商品数据表-{日期}.csv`（供人工补表与归档） |

**导出前检查**（清单全文见 `references/report-template.md` 尾部）：报告 md 排版检查（列表/表格/硬换行三类问题）+ CSV 检查（BOM/列数/待核验标记/链接可回访）。

## 脚本使用（可选，有 Python 环境时更快）

| 脚本 | 用途 | 依赖 |
|---|---|---|
| `scripts/preflight.py` | 报告 md 导出前排版检查 | 无（纯标准库） |
| `scripts/table_check.py` | 商品数据表 CSV 交付前检查 | 无（纯标准库） |
| `scripts/md2pdf.py` | Markdown → PDF（Edge/Chrome 无头渲染，中文排版已调优） | Python + `markdown` 库 + Edge/Chrome |

```
python -I scripts/preflight.py 报告.md
python -I scripts/table_check.py 商品数据表.csv
python -I scripts/md2pdf.py 报告.md 报告.pdf
```

**没有 Python 环境时**：三项检查可直接让智能体读文件逐条核对（检查清单贴给对话即可）；PDF 导出用工作环境自带的文档导出能力完成（如"将这份 markdown 导出为 PDF"）。
