# Step 2 · 六板块完整方法论

六个板块：2.1 政策、2.2 空间与发展、2.3 市场规模、2.4 竞品、2.5 定价、2.6 技术与外观专利。每个板块独立执行，最后在 Step 3 组装成报告。

**执行顺序**：2.0 商品数据表最先（见 `data-collection.md`），2.4 与 2.5 依赖它；其余板块相互独立，可并行。

## 通用规则（执行每个板块时都带在提示词开头）

```
【通用规则】
- 每个数据点带：来源 + 日期 + 置信度（★★★ 官方/多源一致、★★ 单一来源/转述、★ 估算）
- 查不到就写"未获取"，禁止用合理推测填充
- 输出中文；数据段落不放 emoji
- 数据优先：每节先给表格，再给解读
- 销量必须标口径：X+人付款（人数模糊值）/ 30天引单量（联盟渠道）/ 月销量（全站），三者禁止混算
```

## 2.1 政策

回答两层：能不能做（准入）、要做到什么标准（标准与合规）。

```
【政策维度】按两层检索，每层给出"对产品的具体含义"：
1. 准入：需要牌照/资质/备案吗？
2. 标准：强制标准 + 推荐标准，查最新版本年份；列出与本产品相关的具体技术指标

【数据呈现要求】（下表缺一不可）
1. 法规清单表：名称 | 发布机构 | 施行日期 | 效力状态 | 对产品的具体含义
2. 标准清单表：标准号 | 名称 | 强制/推荐 | 施行日期 | 相关技术指标
3. 平台资质表（如适用）：平台 | 类目 | 资质要求

【硬性要求】
- 每条法规标注发布/施行日期与效力状态，避免引用已废止版本
- 涉及专利合规风险时转入 2.6 板块处理，不在此下法律结论
```

---

## 2.2 空间与发展

回答"这个需求有没有在长大"：驱动力、人群规模、已经发生的趋势信号、渠道结构。

```
【空间维度】回答四个问题：
1. 驱动力：技术 / 政策 / 人群 / 成本，什么在推动需求
2. 人群规模：目标人群绝对数量（优先统计口径）
3. 趋势信号：2-3 个"已经发生"的行为信号（有报道支撑的事实，不是"预计""有望"）
4. 渠道结构：线上/线下与平台分布（如可得）

【数据呈现要求】
1. 人群数据表：指标 | 数值 | 年份 | 来源
2. 趋势信号表：信号 | 证据（带来源与日期）| 与本产品的关联
3. 渠道结构表（如可得）：渠道 | 份额/占比 | 来源
```

**要点**：趋势信号只收"已经发生"的事实（如"某平台该品类销量翻了 X 倍"），不收预测性表述——"预计 2027 年将达到"这类句子没有验证价值。

## 2.3 市场规模

回答"这个盘子多大"，并展示口径分歧——不同机构对同一品类的数字可能差好几倍，藏着这些分歧比给一个数字更有价值。

```
【规模维度】
1. 先列至少 2 个来源的大盘数据，展示口径差异
2. 核查口径：是否含服务、是否限材质、是否 To B
3. 若分歧超 3 倍：声明"不采信单一数字"，转而寻找可交叉验证的锚点
   （平台实销数据、上市公司财报）
4. 提供自下而上测算（人群 × 渗透率 × 客单价），标注全部假设与敏感性

【数据呈现要求】
1. 口径对照表：来源 | 数字 | 口径定义 | 年份 | 置信度
2. 测算过程表：变量 | 取值 | 依据 | 敏感性（变动范围）
3. 规模汇总表：TAM / SAM / SOM | 金额 | 计算方式 | 置信度

【硬性要求】
- 区分 TAM / SAM / SOM，禁止用 TAM 讲增长故事
- 自下而上测算标 ★（估算），不得与引用数据混排
```

## 2.4 竞品

回答"谁在抢同一个用户"，重点是结构分组而非罗列。

```
【竞品维度】
1. 按"结构接近度 × 场景重叠度"分组，不是简单罗列
2. 每类竞品给：代表产品、价格、核心卖点、缺陷
3. 产品跨品类时，把所有相邻品类作为竞争线逐一盘点
4. 英文源至少扫描一轮（国际对标）
5. 输出竞争定位图：选两个有区分度的轴，标出本品位置与空白区
6. 评估竞争烈度：对手专注度、价格战风险、壁垒高度

【数据呈现要求】
1. 竞品矩阵表：品牌 | 代表产品 | 价格带 | 核心卖点 | 主要渠道 | 结构近似度
2. 竞争线汇总表：竞争线 | 代表品牌数 | 价格区间 | 竞争烈度
3. 数据表统计摘要：各价格档位 SKU 数、品牌集中度（明细见独立 CSV，报告只放摘要）

【硬性要求】
- 明细数据一律引用商品数据表，不在报告正文另抄一遍
- 必须覆盖"替代方案"（含非产品方案，如"用 Excel 手动做"）
- 空白区分析后加一句：空白 ≠ 护城河
```

## 2.5 定价

回答"卖多少钱合理"，给结构化定价而不是一个孤立数字。

```
【定价维度】
1. 竞品价格带全景（分档位，标代表产品与具体价格）
2. 识别红海区与相对空白区
3. 定价建议绑定三约束：竞品价格带位置、目标人群支付能力、成本结构
4. 优先给"结构化定价"（剃刀-刀片 / 分层 / 场景包），不是单一数字
5. 给出定价逻辑的三条依据

【数据呈现要求】
1. 价格带表：档位 | 价格区间 | 代表产品（带具体价格）| 平台
2. 档位分布：各档位 SKU 数量与占比（从商品数据表统计）
3. 定价对比表：本品建议价 | 最接近竞品价 | 价差 | 依据

【硬性要求】
- 电商价格标注"标价 or 到手价"；大促期（618/双11）数据标注失真风险
- B 端"联系销售"类目标注数据不可得
```

## 2.6 技术与外观专利

回答三个问题：谁在做、做到哪、对本品意味着什么。分技术专利与外观设计专利两部分。

```
【专利维度】分技术专利与外观设计专利两部分，回答三个问题：谁在做、做到哪、对本品意味着什么。

A. 技术专利（发明 + 实用新型）
   1. 检索词：从 Step 1 词表取结构/技术词（如"顶天立地""撑顶""伸缩""免打孔"），必要时用 IPC/CPC 分类号收窄
   2. 数据源优先级：Google Patents（全球+中国，免登录，公开号可回查）→ CNIPA 专利检索系统（官方）→ 佰腾/智慧芽（备选）
   3. 每条列：公开号 | 名称 | 申请人 | 申请日 | 法律状态 | 技术方案一句话 | 与本品机制重合度（高/中/低/不同于）
   4. 格局分析：申请人集中度（是否有大厂把守）、近三年申请趋势、失效专利单独标出（可自由实施的技术富矿）

B. 外观设计专利
   1. 检索范围：同类产品的外观设计，用品类词 + 形态词检索；关注主流竞品是否申请
   2. 每条列：公告号 | 名称 | 申请人 | 申请日 | 法律状态 | 与竞品/本品外观近似度
   3. 重点回答：竞品的视觉资产有没有被保护、本品拟用外观的近似风险

【数据呈现要求】（下表缺一不可）
1. 技术专利清单表
2. 外观设计专利清单表
3. 专利格局汇总表：申请人 | 专利数 | 类型分布 | 法律状态分布 | 意图判断一句话
4. 设计自由度评估表：技术方向 | 专利覆盖情况 | 建议（避开 / 可自由实施 / 需 FTO）

【硬性要求】
- 只列检索到的真实专利，公开号必须可回查（Google Patents 能搜到）
- 不做侵权法律结论；有风险的标注"需专业 FTO"
- 检索词与 Step 1 关键词地图互通——专利文献用词规范，本轮新碰到的术语回流词表
```

**要点**：

- 外观设计专利依法必须附带图片（申请时必交图片或照片），所以每件外观专利都能在官方公告系统（epub.cnipa.gov.cn，凭公开号查询）看到多面视图，是判断"竞品视觉资产"最直接的证据
- 失效专利（未缴年费、保护期届满）是技术富矿——已进入公有领域，可自由实施，单独列出
- 专利数据源不可达时（Google Patents 部分网络环境不可直连、CNIPA 有反爬），可用替代路线：搜索引擎发现专利 → 第三方专利数据库页面核验法律状态 → 公开的说明书全文页补充技术方案；公开号拿到后务必回查确认存在
- 本板块是"设计与 FTO 的先行筛查"，不是法律意见——凡重合度高的，结论都落到"需专业 FTO"上
