# Step 3-4 · 报告组装与导出交付

## Step 3 · 报告组装提示词

```
【任务】组装调研报告。重心：六板块展开 + 数据呈现。

结构（固定）：
1. 执行摘要——数据型：3-5 条核心数据发现 + 1 条总体判断（前置的是数字，不是建议）
2. 研究方法与数据说明：置信度分级定义 + 已知局限 + 商品数据表指引
   （表格在哪、怎么读、数据状态含义）
3. 六板块展开：政策 / 空间与发展 / 市场规模 / 竞品 / 定价 / 技术与外观专利
   （主体，约 70% 篇幅）
4. 简要建议（≤1 页）：1 段定位判断 + 2-3 条条件式行动观察
5. 风险与不确定性（精简版：矩阵保留，说明从简）
6. 附录：关键词地图 + 数据来源清单

【行文规则】
- 每节"先表后文"：以数据表格开场，再给解读；解读篇幅不超过表格体量
- 能用表格说清的不写段落
- 每个板块的"数据呈现要求"表格必须全部出现，不得省略

【硬性要求】
- 每个标题是完整结论（反例："市场规模"；正例："大盘口径分歧剧烈，可及市场需重新测算"）
- 每个数据带来源与置信度
- 结论用条件式（"如果 X 则 Y"），禁止"前景广阔、建议关注"类空话
- 结尾必须有置信度声明与建议复核项（哪些数据多久失效）
- 战略建议总长 ≤1 页；不展开实施路线与资源配置
- 专利板块必须产出设计自由度评估，并明确标注"需专业 FTO"的项目

【篇幅配比】
六板块展开 70% / 摘要与方法说明 10% / 建议与风险 15% / 附录 5%
```

**组装前自查**：六板块的「数据呈现要求」表格是否全部就位——缺表先回 Step 2 补调研，再组装。

**样板参考**：`assets/报告样板-顶天立地架.md` 是用本工作流产出的完整实例，组装前可先浏览一遍，感受"先表后文""标题即结论"的实际落地效果。

## Step 4 · 交付物

两个交付物，同前缀同日期命名，排序时自然配对：

| 交付物 | 文件 | 说明 |
|---|---|---|
| 调研报告 | `{产品名}-市场调研报告-{日期}.md` + `.pdf` | PDF 供阅读与转发 |
| 商品数据表 | `{产品名}-商品数据表-{日期}.csv` | 供人工补表与归档 |

## 报告导出前检查（必做，均有实际踩坑记录）

```
1. 扫描 markdown：列表/代码块紧跟段落且中间无空行 → 补空行
   （否则多数 markdown 转 HTML/PDF 的工具会把列表吸进段落）
2. 文档开头连续元信息行 → 行尾加双空格（硬换行）
3. 表格列数与分隔线一致性检查
4. 导出 PDF
```

- 有 Python 环境：`python -I scripts/preflight.py 报告.md` 自动完成第 1-3 项检查（逐条输出问题位置与修复建议），然后 `python -I scripts/md2pdf.py 报告.md 报告.pdf` 导出
- 无 Python 环境：把上面 4 条清单贴在对话里，让智能体逐条核对；PDF 用工作环境自带的文档导出能力生成

**md2pdf.py 依赖说明**：需要 Python 3 + `markdown` 库（`pip install markdown`）+ 本机装有 Edge/Chrome 浏览器（脚本自动探测，无需配置）。渲染用的是浏览器无头打印，中文排版 CSS 已内置调优（标题、表格、分页控制）。

## 数据表检查

```
1. CSV 编码为 UTF-8 with BOM（Excel 打开乱码 = 没加 BOM）
2. 列头与规范一致，11 列不缺
3. 「待核验」行有醒目标记，人工一眼能找到要补什么
4. 商品链接抽查可回访（从表格里点开能到正确商品页）
```

有 Python 环境时 `python -I scripts/table_check.py 商品数据表.csv` 自动完成第 1-3 项；第 4 项需人工抽查（点开 2-3 个链接验证）。

## 导出完成后的交付话术参考

报告与数据表放在同一文件夹交付，附带一句"数据快照日期"的提醒（价格与销量随日期失效，标注调研时点）——数据表里的采样日期列 + 报告里的复核项清单已经覆盖这一点，交付时口头强调一次即可。
