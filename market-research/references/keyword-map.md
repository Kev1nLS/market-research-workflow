# Step 1 · 关键词地图（完整方法）

**目的**：为一个可能没有品类名的产品，找出市面上同类产品叫什么。

**为什么重要**：产出的词表直接决定 Step 2.0 商品数据表的采集范围——词表越全，搜到的 SKU 越全，后面的竞品与定价分析越可靠。实践中，专利检索和行业术语是命中率最高的两条词源（典型案例：一个没有现成品类名的新形态"立柱挂架"，靠这两条词源挖出了"天地柱""连接柱"等真实行业叫法）。

## 提示词（完整版）

```
【任务】找出目标产品的所有同类名称与关键词。

A. 八角度展开（每角度至少 3 个候选词，不做同义词替换）：
   1. 结构/形态词（它长什么样）
   2. 品类词（可能归到哪个类目）
   3. 材质/技术词（用什么做的、什么工艺）
   4. 场景词（用户在什么情境下需要它）→ 跨品类竞品的入口
   5. 人群词（谁会买）
   6. 行业术语（B 端/专业领域怎么称呼）→ 实测命中率最高
   7. 品牌词（知道一个就能顺藤摸瓜）
   8. 英文词（国际对标）

B. 五个高质量词源（按优先级）：
   1. 专利检索：结构描述词搜专利库——专利文献用词规范，且直接证明"有人做过"
   2. 行业术语：查目标行业的 B 端叫法（实测案例："天地柱""连接柱"一击命中）
   3. 电商搜索联想词 / 类目树
   4. 品牌顺藤摸瓜
   5. 行业报告与媒体文章

C. 命中验证循环（必须执行）：
   每个候选词实搜一次 → 判断结果是否真同类 → 命中则保留并从结果挖新词，
   未命中则丢弃 —— 循环到不再出现新词（信息饱和，通常 3-4 轮）

【硬性要求】
- 产出必须是"用户实际会搜的词"，不是"描述产品的话"
- 词表带标签：词 | 类型 | 来源 | 命中判定
- 区分"直接同类"与"跨品类竞品"（同一 Job 不同形态）

【产出】关键词地图（表格）+ 类似产品清单（按结构接近度分组，附价格区间）
```

## 方法要点

**八角度**的用意：同一个东西会以完全不同的名字出现——用户按"场景词"搜，商家按"结构词"命名，专业人士用"行业术语"，专利文献用规范描述。八个角度各扫一遍，才不漏。

**五词源的优先序**不是随意的：专利文献和行业标准文书用词最规范、最稳定（"撑顶式晾衣架"这类词只有它们会用），所以命中率最高；电商联想词反映真实搜索行为；品牌词用于顺藤摸瓜找同款；行业报告兜底。

**验证循环**不能省：AI 列出的候选词里必然混着"看着像但搜出来不是同类"的词，逐个实搜剔除，并从命中的结果页继续挖新词，直到 3-4 轮后不再冒新词（信息饱和）。

**产出格式**：

| 词 | 类型 | 来源 | 命中判定 |
|---|---|---|---|
| 顶天立地衣架 | 结构/形态词 | 电商联想词 | 命中，直接同类 |
| 天地柱 | 行业术语 | 专利检索 | 命中，直接同类（B 端叫法） |
| … | … | … | 未命中，丢弃 |

类似产品清单按结构接近度分组（直接同类 / 邻近形态 / 跨品类竞品），每组给出代表产品与价格区间——这份清单就是 Step 0 确认的"调研边界"在实例上的落地，也是 Step 2.0 建表的起点。

## 与其他步骤的衔接

- **上游**：Step 0 的调研简报确定边界（什么算同类）；本步在边界内展开词表
- **下游**：词表全部交给 Step 2.0 做采集；专利板块（2.6）的检索词也从词表的结构/技术词取用
- **回流**：专利检索中新碰到的术语（如"撑顶""免打孔"）回流补充词表，两边互通
